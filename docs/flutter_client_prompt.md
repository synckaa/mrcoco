# Flutter Client Development Prompt — MrCoCo App

## Overview

Build a Flutter client application for **MrCoCo** — an inventory and purchase management system. The app connects to a REST API backend at `http://localhost:8080/api`. The app must support both **desktop** and **mobile** layouts with responsive design.

---

## Tech Stack & Conventions

- **State Management:** Provider (most popular, simple, widely supported)
- **HTTP Client:** `http` or `dio` package
- **Design:** Material Design 3, responsive (desktop sidebar + mobile drawer/bottom nav)
- **Architecture:** Feature-based folder structure
- **Code Style:** Clean code, snake_case files, PascalCase classes

---

## CRITICAL: API Request/Response Format Rules

> **READ THIS BEFORE WRITING ANY API CALL CODE**

### Date Fields
- All date fields (`tanggal`, `tgl_jatuh_tempo`, `start_date`, `end_date`) MUST use format **`"YYYY-MM-DD"`**
- Example: `"2026-09-05"`, `"2026-10-01"`
- NEVER send datetime format like `"2026-09-05T00:00:00Z"` — the backend only accepts date-only

### Auto-Generated Fields (DO NOT SEND)
- `no_transaksi` is auto-generated by the backend. NEVER include it in POST or PUT request bodies
- `id` is auto-generated. NEVER include it in POST request body
- `created_at`, `updated_at` are auto-generated

### Content-Type
- All POST and PUT requests MUST set header: `"Content-Type": "application/json"`

## Pembelian Module

**Endpoint:** `GET /api/pembelian`

**Filter bar (top of page):**
- Date Range Picker → `start_date` and `end_date` query params (format: `YYYY-MM-DD`)
- Supplier Dropdown → `supplier_id` query param (fetch suppliers from `GET /api/supplier`)
- Search by No Transaksi → `no_transaksi` query param
- Filter button + Reset button

```
GET /api/pembelian?start_date=2026-09-01&end_date=2026-09-30

GET /api/pembelian?no_transaksi=202609
```

### 2. Pembelian Create/Edit Page

This is a **dedicated full page** (not a modal/dialog).

#### Step 1: Fetch Next No Transaksi

When opening the form for **create** (not edit), fetch the next no transaksi:

**Request:**
```
GET /api/pembelian/next-no
GET /api/pembelian/next-no?tanggal=2026-10-05
```

**Response 200:**
```json
{
  "no_transaksi": "2026100001"
}
```

Display this as **read-only** on the form. The `tanggal` query param is optional — if not provided, uses current server date.

#### Step 2: Fetch Dropdown Data

- **Supplier:** `GET /api/supplier?page=1&limit=100`
- **Gudang:** `GET /api/gudang?page=1&limit=100`
- **Rekening:** `GET /api/rekening?page=1&limit=100`

#### Step 3: Search & Add Items

When user types in item search bar:

**Request:**

**Auto-calculated fields:**

- `jumlah_uang_sisa` = `grand_total - jumlah_uang_muka`

### Pembelian API Endpoints Summary

| Method | Endpoint | Description | Body Fields |
|--------|----------|-------------|-------------|
| GET | /api/pembelian | History (filter: start_date, end_date, supplier_id, no_transaksi) | — |

| GET | /api/pembelian/next-no?tanggal=YYYY-MM-DD | Next auto-generated no transaksi | — |

| DELETE | /api/pembelian/:id | Delete (cascade items) | — |

- Date format for API: `YYYY-MM-DD`
- Show **snackbar** for success/error after CRUD operations
- Show **loading spinner** during API calls

## Key Behaviors

1. **Pagination:** Load 10 items per page, show page navigation
2. **Search:** Real-time search with debounce (300ms), supports multi-word smart search
3. **Create:** After successful create, show success snackbar and navigate back to list
4. **Edit:** Pre-fill form with existing data, save updates
5. **Delete:** Show confirmation dialog, after successful delete refresh list
6. **Refresh:** Manual refresh button re-fetches current page data
7. **Pembelian no transaksi:** Fetch from `GET /api/pembelian/next-no?tanggal=YYYY-MM-DD` when opening create form. Update preview when user changes tanggal
8. **Pembelian item subtotal:** Auto-calculate: `subtotal = (qty * harga) - diskon`
9. **Pembelian grand total:** Auto-calculate: sum of all item subtotals
10. **Pembelian uang sisa:** Auto-calculate: `grand_total - jumlah_uang_muka`
11. **Pembelian date format:** Always send `"YYYY-MM-DD"` for tanggal and tgl_jatuh_tempo

## Common Mistakes to Avoid

1. ❌ Sending `no_transaksi` in POST/PUT body → Backend auto-generates it
2. ❌ Sending `id` in POST body → Backend auto-generates it
3. ❌ Sending date as `"2026-09-05T00:00:00Z"` → Use `"YYYY-MM-DD"` only
4. ❌ Missing `Content-Type: application/json` header → Always set it for POST/PUT
5. ❌ Sending `created_at` or `updated_at` → Backend auto-manages these
6. ❌ Using `null` for optional fields → Can omit them entirely from body
